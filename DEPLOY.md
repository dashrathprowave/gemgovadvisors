# Deploying to the VPS (Enhance panel)

This is a **Next.js app**, so it runs as a Node process behind Enhance's web
server. It is not a PHP site — copying files into `public_html` will not work.

**Upload `deploy.tar.gz` — not the whole project.** The whole project would need
`npm install` and `next build` on the VPS, which is slow and often runs out of
memory on small instances. The bundle is already built and carries only the
packages it needs.

---

## 1. On your computer — build the bundle

```bash
npm install
npm run bundle
```

This creates `deploy/` — and `deploy.tar.gz`, the same thing as one file, which
is what you upload. The bundle contains:

| | |
| --- | --- |
| `server.js` | the app — this is what gets started |
| `node_modules/` | trimmed, includes `mysql2` and `nodemailer` |
| `.next/`, `public/` | the built site, styles and images |
| `db/schema.sql` | the database tables |
| `scripts/` | `db-setup.mjs`, `db-check.mjs`, `mail-test.mjs`, `db-export.mjs` |

`.env.local` and the `data/` folder are deliberately **not** included — secrets
and stored enquiries belong on the server only.

---

## 2. In Enhance — create the website, database and mailbox

1. **Websites → New website**, add `gemgovadvisors.com`.
2. **Databases → New database**. Write down the database name, user and
   password Enhance generates — you need them in step 4.
3. **Email → New mailbox**, create `gem@gemgovadvisors.com` and set a password.
4. Turn on **SSL** for the domain (Let's Encrypt is built in).

---

## 3. Upload

**Upload `deploy.tar.gz` — the single archive `npm run bundle` also produces —
and unpack it on the server:**

```bash
cd ~/public_html
rm -rf .next                            # the old build must go first
tar -xzf deploy.tar.gz && rm deploy.tar.gz
```

`start.js` must end up at the top level of the site directory.

> **Why `rm -rf .next` matters.** `tar` overwrites but never deletes. Extracting
> a new build on top of an old one leaves `.next/server` and `.next/static`
> holding files from two different builds. The page is then generated by one
> build while asking for asset filenames from the other, and those files are not
> on disk — Apache misses them, passes the request to Node, and you get a 500 on
> a stylesheet with everything else working.

> **Do not upload the folder file-by-file.** `.next/static` contains thousands of
> small files, and FTP or a web file manager routinely drops or truncates a few
> of them. A single missing CSS chunk returns a 500 and the whole site loses its
> styling and responsive layout, with nothing in the logs to explain it. The
> archive is one file, so it either arrives or it does not.

Unpacking never touches `.env.local`, so your settings survive a redeploy.

---

## 4. Create `.env.local`

Over SSH, in the same directory as `server.js`:

```bash
nano .env.local
```

Paste this and fill in the two passwords:

```bash
# Enhance runs MySQL on a unix socket, not a TCP port. Check the path with
# `ls -la /run/mysqld` if this one does not exist.
MYSQL_SOCKET=/run/mysqld/mysqld.sock
MYSQL_USER=<database user from Enhance>
MYSQL_PASSWORD=<its password>
MYSQL_DATABASE=<database name from Enhance>

SMTP_HOST=smtp.hostinger.com
SMTP_PORT=465
SMTP_USER=gem@gemgovadvisors.com
SMTP_PASSWORD=<the mailbox password>

HOSTNAME=0.0.0.0
```

Two things that matter:

- **`HOSTNAME=0.0.0.0`** — Enhance reaches the app through a reverse proxy. An
  app bound only to `localhost` gives a 502.
- **Do not set `PORT`** — Enhance assigns it.

If port 465 is blocked on your VPS, use `SMTP_PORT=587` instead.

If your host does expose MySQL over TCP instead of a socket, drop
`MYSQL_SOCKET` and use `MYSQL_HOST` / `MYSQL_PORT` — prefer `127.0.0.1` over
`localhost`, which can resolve to IPv6 where MySQL is not listening.

---

## 5. Create the database tables

Still over SSH, from the same directory:

```bash
node scripts/db-setup.mjs
```

Expected:

```
Connected to "yourdb" on socket /run/mysqld/mysqld.sock
  ✓ leads — ready (0 rows)
  ✓ registrations — ready (0 rows)

Database is ready.
```

Then confirm everything is wired up:

```bash
node scripts/db-check.mjs
```

This prints the row counts and, importantly, the last line should read
`Email alerts: SMTP (smtp.hostinger.com as gem@gemgovadvisors.com)`. If it says
`OFF`, the `SMTP_*` values are missing or misspelled.

---

## 6. Test the email before going live

```bash
node scripts/mail-test.mjs
```

This connects, authenticates and sends one real test email, so a mail problem
surfaces here rather than on a customer's enquiry that never reaches you.

```
Connecting and authenticating... OK
Sending test email...            OK

Sent. Message id: <...>
```

To send it somewhere else for the check:

```bash
node scripts/mail-test.mjs you@gmail.com
```

Common failures and what they mean:

| Message | Fix |
| --- | --- |
| `EAUTH ... authentication failed` | `SMTP_USER` must be the full email address, and `SMTP_PASSWORD` the **mailbox** password — not your hosting panel login |
| `ETIMEDOUT` / `ESOCKET` | Port 465 is blocked — set `SMTP_PORT=587` in `.env.local` |
| `EENVELOPE` | `SMTP_FROM` must be a real mailbox on your own domain |

If the mail arrives but lands in Spam, add the SPF and DKIM records below.

---

## 7. Start the app

In Enhance, on the website, use the **Deploy Node.js** tool:

- **Application root** — the directory you uploaded into
- **Startup file** — `start.js`  ← not `server.js`
- **Node version** — 20 or newer

Enhance starts the process, keeps it alive, and proxies the domain to it.

`start.js` reads `.env.local` itself and then hands over to `server.js`. Next's
own env loader is not reliable when a panel starts the process, and when it
silently does not fire the app answers requests normally while having no
database and no mail settings — enquiries then fall through to `data/` with no
visible error.

Its first log line tells you whether that worked:

```
[start] env vars loaded: 9 | database: configured | email: configured
```

If either says `MISSING`, `.env.local` is not being read — check it sits next to
`start.js`.

To sanity-check by hand over SSH first:

```bash
PORT=3000 HOSTNAME=0.0.0.0 node start.js
```

then in another session `curl http://localhost:3000` should return HTML.

---

## 8. Verify the live site

1. Open `https://gemgovadvisors.com` — styling and images should load.
2. Submit the form at `/register`.
3. You should land on the thank-you page.
4. Check the row arrived:
   ```bash
   node scripts/db-check.mjs
   ```
5. Check the alert email reached `gem@gemgovadvisors.com`.

If steps 1–3 work but no row appears, the app fell back to writing
`data/registrations.json` — the enquiry is safe, but `MYSQL_*` is wrong. Fix it
and restart.

## Updating the site later

On your computer:

```bash
npm run bundle
```

Upload the new `deploy.tar.gz`, then on the server:

```bash
cd ~/public_html
rm -rf .next
tar -xzf deploy.tar.gz && rm deploy.tar.gz
```

Then **restart the app from Enhance** — this is not optional. Until the process
restarts it keeps serving the previous build from memory, which asks the browser
for asset filenames that the new upload no longer contains. `.env.local`, `data/` and the database are
all left untouched.

`npm run bundle` only works on your computer — the server has no Next CLI, so
running it there gives `next: not found`. The bundle's own `package.json` lists
only the commands that do work on the server.

## Email deliverability

Mail is sent from your own domain's mailbox, so these DNS records must exist or
alerts will land in spam. Hostinger usually adds them for mailboxes it hosts —
confirm they are there:

- **SPF** — `v=spf1 include:_spf.mail.hostinger.com ~all`
- **DKIM** — the record Hostinger generates for the domain
- **DMARC** — `v=DMARC1; p=none; rua=mailto:gem@gemgovadvisors.com`

## Reading the enquiries

```bash
node scripts/db-check.mjs     # counts and the most recent submission
node scripts/db-export.mjs    # writes exports/*.csv, opens in Excel
```

You can also browse the `registrations` and `leads` tables in phpMyAdmin. Both
have a `status` column (defaults to `new`) and a `notes` column for tracking
follow-ups.

## If something goes wrong

| Symptom | Cause |
| --- | --- |
| 502 / bad gateway | App not running, or `HOSTNAME` is not `0.0.0.0` |
| Site loads but layout is broken / looks like mobile on desktop | A CSS chunk 500s. Either the upload was partial, or `.next` holds two builds at once. Fix: `rm -rf .next`, re-extract `deploy.tar.gz`, restart the app |
| One asset 500s while others in the same folder are fine | Check its response headers. An Apache-style `ETag: W/"..."` means Apache served it from disk; a short Next-style `ETag: "..."` with `Cache-Control: no-store` means Apache could not find the file and passed it to Node. The file is missing — the deployed build is mixed |
| Form succeeds but no database row | `MYSQL_*` wrong; check `node scripts/db-check.mjs`, the enquiry is in `data/registrations.json` |
| No alert emails | `SMTP_*` wrong, or port 465 blocked — try 587 |
| `next: not found` | You ran `npm run bundle`/`npm run build` on the server — those are computer-only commands |
| Form shows success but nothing in the database or inbox | The app cannot see `.env.local`. Check the `[start]` log line says `configured` for both, and that the panel's startup file is `start.js` |
| `Cannot find module 'mysql2'` | Bundle built without `serverExternalPackages` — rebuild with the current `next.config.mjs` |
